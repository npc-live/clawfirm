# 视频章节/时间线写作指南

为视频生成结构化章节时间线，提升用户体验和平台 SEO。

---

## 平台支持情况

| 平台 | 支持方式 | 格式要求 |
|------|----------|----------|
| YouTube | 描述内嵌时间戳，自动识别为可点击章节 | `MM:SS 标题`，必须从 `0:00` 开始，≥3 个节点 |
| B站 | 描述内嵌时间戳（视频看点），自动识别 | `MM:SS 标题`，从 `00:00` 开始，3-9 个节点，标题≤16字 |
| 小红书 | 发布页"章节编辑器" UI 填写 | `MM:SS 标题`，通过 UI 逐条添加 |
| 抖音 | 发布页"看点/章节" UI 填写 | `MM:SS 标题`，通过 UI 逐条添加 |
| TikTok | 不支持 | — |
| LinkedIn | 不支持 | — |
| 微信视频号 | 不支持 | — |
| Twitter/X | 不支持 | — |

---

## 统一时间戳格式

```
格式: MM:SS 章节标题

规则:
  - 分钟和秒都用两位数字（00:00, 01:30, 12:45）
  - 超过 1 小时用 H:MM:SS（1:02:30）
  - 每行一个时间戳
  - 标题与时间戳之间用一个空格分隔

示例:
  00:00 开场引言
  01:30 核心概念介绍
  04:20 实操演示
  07:00 常见问题解答
  09:45 总结与下期预告
```

---

## 章节数量建议

| 视频时长 | 建议章节数 | 说明 |
|----------|-----------|------|
| 3-5 分钟 | 3-5 个 | 短视频保持精简，每章节1分钟左右 |
| 5-10 分钟 | 5-8 个 | 中视频标准密度 |
| 10-20 分钟 | 8-15 个 | 长视频需要更细的导航 |
| 20-60 分钟 | 15-25 个 | 深度内容，每1-3分钟一个节点 |

```
核心原则:
  - 章节应标记话题转折点，不是每句话
  - 宁可少不可滥 — 过多章节失去导航意义
  - 第一个章节必须是 00:00（开场/引言）
  - 最后一个章节建议是总结/结语
```

## 章节标题写作规范

### 基本规则

```
字数: ≤15 字（中文）/ ≤30 字符（英文）
风格: 简洁明了，一看就知道该段讲什么
关键词: 包含该段核心关键词（利于搜索）
```

### 标题公式

| 公式 | 示例 |
|------|------|
| 动词 + 对象 | "配置开发环境" |
| 名词短语 | "性能优化技巧" |
| 问题式 | "为什么要用 TypeScript？" |
| 数字 + 主题 | "3 个常见错误" |
| 对比式 | "React vs Vue 对比" |

### 中英双语

```
中文章节:
  00:00 开场
  01:30 什么是 RAG
  04:20 搭建向量数据库
  07:00 实现检索增强
  09:45 效果对比与总结

English chapters:
  0:00 Introduction
  1:30 What is RAG?
  4:20 Setting Up Vector DB
  7:00 Implementing Retrieval
  9:45 Results & Wrap-up
```

## 章节生成策略

### 策略 1: 从 SRT 字幕提取

当视频已有 SRT 字幕文件时，从字幕内容中提取话题转折点。

```
输入: SRT 字幕文件
方法: 识别话题变化点（语义分析），提取对应时间戳
输出: MM:SS 章节标题（10-20 个节点）

注意:
  - 只提取主要话题转折点，不是每句话
  - 合并相近时间点的内容（≤30 秒的间隔可合并）
  - 标题从字幕内容概括，不直接复制原文
```

### 策略 2: 从脚本大纲生成

当视频有脚本或大纲但尚未制作/时间不确定时，生成章节规划。

```
输入: 视频脚本/大纲 + 预估总时长
方法: 根据脚本段落分配时间，生成等比例时间戳
输出: MM:SS 章节标题

注意:
  - 时间戳基于内容比例估算，发布前需根据实际视频调整
  - 标记为"预估时间线"，提醒后续校正
```

### 策略 3: 从视频主题规划

当只有视频主题时，生成推荐章节结构。

```
输入: 视频主题 + 类型（教程/评测/分析/vlog）
方法: 基于内容类型的标准结构模板生成章节框架
输出: 章节标题列表（不含时间戳，待实际制作后补充）

教程类标准结构:
  开场引言 → 背景/为什么 → 工具准备 → 步骤1 → 步骤2 → ... → 常见问题 → 总结

评测类标准结构:
  开场 → 产品概览 → 外观/设计 → 性能/功能测试 → 优缺点 → 与竞品对比 → 购买建议

分析类标准结构:
  开场 → 现象/事件概述 → 原因分析 → 数据佐证 → 影响预测 → 结论/建议
```

## 平台特殊规则

### YouTube

```
硬性要求:
  - 必须从 0:00 开始（否则不识别为章节）
  - 至少 3 个时间戳
  - 每个章节至少 10 秒长
  - 时间戳写在视频描述中

格式位置（描述中）:
  [核心摘要 — 折叠前可见]
  [CTA]
  
  ⏱️ Chapters:
  0:00 Introduction
  1:30 First Topic
  4:20 Second Topic
  ...
  
  [链接和标签]

SEO 加成:
  - 章节标题中的关键词会被 Google 索引
  - 搜索结果可直接显示章节锚点（Key Moments）
  - 章节提高用户留存率（可跳转到感兴趣的部分）
```

### B站

```
硬性要求:
  - 时间戳写在简介/描述中
  - 格式: MM:SS 标题（每行一个）
  - 从 00:00 开始，3-9 个节点（不能超过 10 个）
  - 每个章节标题≤16 字
  - B站自动识别为"视频看点"

格式位置（简介中）:
  [视频简介正文]
  
  00:00 开场
  01:30 第一部分
  04:20 第二部分
  ...

特点:
  - B站播放器底部会显示章节标记
  - 用户可点击跳转
  - 弹幕密度会在章节边界处变化
```

### 小红书 & 抖音

```
特点:
  - 通过发布页 UI 编辑器添加，不是写在文案中
  - 格式同样是 MM:SS + 标题
  - 发布时由 CDP 自动化填入 UI

注意:
  - 生成时仍按 MM:SS 标题 格式输出
  - 上传脚本会解析并逐条填入平台 UI
  - 章节数量不宜过多（短视频3-5个即可）
```
